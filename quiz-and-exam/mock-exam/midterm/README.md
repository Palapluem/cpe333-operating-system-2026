## ข้อตกลงตัวเลขสำหรับเฉลย

- Scheduling: bursts 10,1,2,1,5 ms รวม 19 ms; arrivals 0; RR q=1 ms ตามต้นฉบับ เฉลยใช้ SJF ties ตามลำดับเดิมและ overhead 0 เป็นข้อตกลงทำเฉลย ไม่เพิ่มลงในโจทย์ และรับ tie ที่สอดคล้องกับ policy และคำนวณถูกต้อง; priority column คงไว้ตามเรฟแต่ไม่ใช้ในสาม policies นี้
- Replacement: 3 frames; reference string 20 ตัวตามภาพ เฉลยเริ่ม frames ว่างและได้ FIFO/LRU/OPT faults = 13/13/10 ไม่เติมเงื่อนไขเริ่มว่างหรือคำสั่งให้รายงาน H/F/counts/probability ลงในโจทย์ที่ต้นฉบับไม่มี
- OPT ไม่บังคับ tie-break ในข้อสอบ เฉลยเลือก frame ต่ำสุดเพื่อให้ตารางทำซ้ำได้ และยอมรับตารางอื่นที่ optimal เช่นกัน
- EAT ใช้โมเดล Lecture 6 หน้า 29: (1-p)m+pD โดย m = memory access 10 ns, D = disk access 10 ms; ไม่อ้างว่าโจทย์ต้นฉบับระบุ complete fault-path/restarted access และไม่เพิ่มสมมติฐานดังกล่าวลงในตัวข้อสอบ rubric ข้อ 3 แยกตาราง 6 คะแนนและ EAT 2 คะแนนโดยไม่เพิ่มคำถามย่อยหรือบังคับแถว H/F
- แยก response ออกจาก total waiting time และ TLB miss ออกจาก page fault

## Build / ทดสอบ

ต้องมี Python 3.10+, PyMuPDF, Pillow, XeLaTeX พร้อม exam/fontspec/polyglossia/tikz/svg และ dependencies รวมถึง Inkscape ใน PATH ฟอนต์อ่านจาก fonts/ ที่แนบมา

    cd quiz-and-exam/mock-exam/midterm
    python3 build.py
    python3 build.py --check-only
    python3 -m unittest -v test_mock_exam.py
    python3 -B build.py --clean

แก้ปรนัย/short answer ใน question-bank.json; แก้โจทย์อัตนัยและ rubric ใน build.py; generated .tex จะถูกสร้างใหม่ ห้ามแก้ generated files แทน source

build ใช้ jobname ไม่มีช่องว่างเพื่อรองรับ svg/ifplatform แต่คงชื่อ PDF มาตรฐานที่มีช่องว่างไว้ให้ wrapper ใช้ตามเดิม

`--clean` ย้ายเฉพาะไฟล์ build ที่รู้ชื่อแน่นอนไปโฟลเดอร์พักกู้คืนในระบบ (พิมพ์ path หลังทำเสร็จ) ได้แก่ aux/log/cache, PDF ของ internal job และสำเนา PDF รวม/เฉลยที่ซ้ำกับ output/pdf ไม่แตะข้อสอบเก่า เอกสารเตรียมสอบ source, fonts, logo, generated .tex, PDF component สองไฟล์ที่ main wrapper ต้องใช้ หรือ PDF ใช้งานสองเล่มใน output/pdf ไฟล์พักเหล่านี้สร้างใหม่ได้ด้วย build; `--check-only` และ tests ยังทำงานหลังล้างได้โดยใช้ `python3 -B` เพื่อไม่สร้าง Python cache ใหม่ ส่วนการตรวจ glyph/overflow จาก log ทำก่อนล้างใน build ทุกครั้ง
